# CR-02: Gameplay feedback polish

## Objective and context

Make in-mission feedback clearer and more responsive for a cooperative three-role crew. Inspect the current UI, authoritative engine, and tests before choosing implementation points.

## Dependencies

None. Avoid overlapping work with CR-03 or CR-07 unless lanes are coordinated.

## Invariants

The server remains authoritative for actions, time, damage, and outcomes. Preserve Solar Storm timings/rules, role-specific information, anonymous Supabase auth, reconnect/retry, and multiplayer privacy. UI feedback must reflect server-confirmed state rather than imply an uncommitted action succeeded.

## Scope

Improve action feedback, warnings, success/failure cues, urgency, and visibility of shared crew dependencies. Add animation or sound hooks only when they fit existing architecture and remain accessible. Keep cooperative framing.

## Non-goals

Do not change authoritative game rules, add mission content, create individual rankings, or alter the roadmap/workflow tooling.

Keep edits to `ROADMAP.json`, other goal prompts, goal CLI scripts, and workflow documentation out of scope.

## Definition of done

- Important actions and server responses have clear pending/success/error feedback.
- Warnings communicate urgency and the relevant cross-role dependency.
- Reduced-motion and keyboard/accessibility behavior remain usable.
- Tests preserve server authority and do not rely on presentation-only success.

## Validation and completion

Inspect current implementation and relevant tests; do not assume filenames. Run lint, typecheck, unit/API tests, build, relevant browser/live validation where available, and `git diff --check`. Check desktop and approximately 390 px mobile layouts. Do not weaken assertions. If any criterion cannot be met, report this goal as incomplete and explain why. Review and commit locally; do not push or deploy.
