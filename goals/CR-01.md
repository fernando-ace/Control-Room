# CR-01: Multi-mission architecture

## Objective and context

Make the current Solar Storm mission one selectable mission in a small extensible mission model, creating a safe foundation for later missions. The current application is a cooperative three-player browser game with a server-only pure TypeScript engine in `lib/engine.ts`, Supabase persistence, and role-filtered station snapshots. Inspect the implementation before assuming filenames or boundaries.

## Dependencies

None. This is a core, low-parallel-safety change. Work in isolation and coordinate integration before merging.

## Invariants

Preserve current Solar Storm gameplay exactly: three players, Commander/Pilot/Engineer, current role duties and private secrets, phase timing, authoritative server timestamps, server-side outcomes, revision/CAS behavior, action deduplication, reconnect and retry, and privacy/security boundaries. Keep anonymous Supabase auth and server-only secrets unchanged.

## Scope

- Introduce only the mission identity/configuration seam needed to support more than one mission.
- Keep Solar Storm as the default and preserve its current display, action, and simulation behavior.
- Update persisted types, snapshots, API handling, and tests only as needed to represent mission identity safely.

## Non-goals

Do not add another mission, change Solar Storm rules or timings, redesign screens, alter database security, or deploy.

## Definition of done

- Existing Solar Storm behavior and authoritative simulation remain unchanged.
- Mission selection/identity cannot be forged by a client or leak private data.
- Tests cover mission identity through creation, persistence/snapshot, and retry as applicable.
- Existing gameplay and privacy assertions remain intact.

## Validation and completion

Inspect relevant implementation and tests first. Run lint, typecheck, all unit/API tests, production build, and relevant live multiplayer validation if credentials are available. Run `git diff --check`. Do not weaken tests or safety guarantees. If acceptance cannot be met, report this goal incomplete and state why. Review the diff and commit completed work locally; do not push or deploy.
