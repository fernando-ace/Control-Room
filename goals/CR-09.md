# CR-09: Adversarial verification

## Objective and context

Independently try to falsify the integrated implementation. Assume it may be wrong. Inspect source, tests, and the integration diff before relying on prior reports.

## Dependencies

CR-08 must be complete and integrated.

## Invariants

Do not weaken acceptance criteria or assertions. Preserve server authority, role privacy, anonymous-auth assumptions, mission timing, outsider isolation, deterministic behavior, reconnect, and retry.

## Scope

Probe fake/hardcoded success, weak assertions, races, reconnect and stale state, role leaks, client-authority regressions, timing/deadline bugs, outsider access, retry contamination, responsive overflow, and multiplayer flakiness. Fix legitimate defects with regression tests.

## Non-goals

Do not rewrite working features without evidence, delete coverage, or report unexecuted checks as passed.

## Definition of done

- Each listed risk area has a concrete inspection or test result.
- Any found defect has a regression test and a scoped fix, or is documented as unresolved.
- All required local checks pass; live checks are run where possible and otherwise clearly identified as unverified.
- No acceptance assertion or safety guarantee was weakened.

## Validation and completion

Inspect implementation and tests rather than assuming filenames. Run lint, typecheck, all unit/API tests, production build, live multiplayer/browser validation if available, and `git diff --check`. Report incomplete if evidence is insufficient. Review and commit completed fixes locally; do not push or deploy.
