# CR-08: Parallel feature integration

## Objective and context

Integrate completed parallel feature branches into the current accepted base, resolve cross-feature inconsistencies, and establish that the complete Control Room still works. Inspect Git history/status, every incoming diff, and architecture before merging.

## Dependencies

CR-01 through CR-07 must be completed and their accepted work integrated or explicitly judged unnecessary with documented evidence. Roadmap dependency state is a minimum gate, not proof that branches were merged.

## Invariants

Do not silently discard feature behavior, lower acceptance criteria, weaken security/timing/role/reconnect guarantees, or change authoritative server logic without preserving tests. Keep unrelated work untouched.

## Scope

Review incoming branches, merge accepted work, resolve architectural mismatches, run the full local test/build suite, and run the live multiplayer/browser suite when credentials/services are available. Fix integration defects.

## Non-goals

Do not start unrelated product features, deploy, or mark a feature complete solely because its branch exists.

## Definition of done

- All accepted prerequisite work is integrated and reviewed.
- Full lint, typecheck, unit/API tests, production build, and relevant live/browser validations pass.
- Desktop/mobile and security/privacy invariants still hold.
- Integration limitations are recorded honestly; missing live evidence is not represented as a pass.

## Validation and completion

Inspect repository state and every merge diff. Run all required checks, including `git diff --check`. Never reduce assertions to obtain green results. Report incomplete if any gate or integration item remains. Commit integration locally; do not push or deploy.
